# 发布流程

面向维护者。普通使用者直接从 [Releases](https://github.com/YesXXX/claude-nexus/releases) 下载安装包即可。

## 签名机制

每次发版产出两样东西：安装包 `ClaudeNexus-Setup-vX.Y.Z.exe`，以及签名清单 `latest.json`（版本号、文件名、大小、sha256、更新说明，整体用 Ed25519 私钥签名）。客户端用内嵌在 `src/main/update-pubkey.ts` 的公钥验签，再校验安装包大小与 sha256，全部通过才会拉起安装器。

## 首次准备密钥

```bash
npm run keygen
```

- 私钥写到 `%USERPROFILE%\.claude-panel-signing\update-ed25519.pem`（可用 `CLAUDE_PANEL_SIGN_KEY` 改路径），只放在本机，绝不进仓库，离线备份两份
- 公钥写入 `src/main/update-pubkey.ts`（需要提交）；私钥已存在时拒绝覆盖，重新生成需 `npm run keygen -- --force`，换钥后旧客户端将无法验证新签名
- fork 本项目自行发布时必须生成自己的密钥对，否则你的清单无法通过原作者公钥的校验

## 发版步骤

1. 修改 `package.json` 的 `version`（新功能升次版本号，纯修复升补丁号）
2. 在 `更新说明/vX.Y.Z.md` 写本版要点，每行一条 `- `，面向使用者；这份内容会被签名，显示在客户端更新弹窗与 GitHub Release 正文里。同时在 `CHANGELOG.md` 顶部补上本版条目
3. 出包并签名：`npm run dist`（私钥有口令时设 `CLAUDE_PANEL_SIGN_KEY_PASS`），产物在 `release/`
4. 提交到 main 并打 tag：`git tag vX.Y.Z && git push origin main vX.Y.Z`
5. 发布到下面任意一个或两个渠道

## 发布到 GitHub Releases

```bash
# 先只做本地校验，看看会上传什么
npm run publish-github -- --dry-run

# 创建草稿 Release 并上传附件，到网页上检查后手动公开
GITHUB_TOKEN=<token> npm run publish-github

# 或直接公开
GITHUB_TOKEN=<token> npm run publish-github -- --publish
```

- token 用 fine-grained personal access token，只授权本仓库的 Contents 读写
- 仓库默认取 `package.json` 的 `repository.url`，可用 `GITHUB_REPOSITORY=owner/repo` 覆盖
- 上传三个附件：安装包、`latest.json`、`SHA256SUMS.txt`；重复执行会跳过大小一致的附件，可以放心重跑
- 要求 tag 已推送到 GitHub，Release 挂在这个 tag 上

## 发布到共享目录（团队内部分发）

```bash
npm run publish-update -- --to \\服务器\共享\claude-nexus
```

校验后先拷安装包、最后写 `latest.json`，并清理旧版本安装包；不加 `--to` 时用环境变量 `CLAUDE_PANEL_UPDATE_DIR`，再缺省为项目根下的 `update/`。使用者在面板左下角「检查更新」里把更新目录设为这个共享目录即可自动收到更新。

## 调试更新流程

开发态下手动「检查更新」不受安装版限制；可用 `CLAUDE_PANEL_UPDATE_TEST_PUBKEY` 指向一把测试公钥 PEM 追加到验签公钥列表（仅开发态生效，安装版忽略），再用对应的测试私钥（`CLAUDE_PANEL_SIGN_KEY` 指过去）签出清单，就能在不动正式密钥的情况下走通整条更新链路。
