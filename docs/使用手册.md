# 使用手册

完整功能说明。快速上手见 [README](../README.md)，参与开发见 [开发指南](开发指南.md)。

## 会话列表与属性面板

界面只常驻和当前操作有关的信息：快捷键写在按钮与行的悬停提示里，完整一览在设置页「快捷键」分节与命令面板（命令右侧显示按键）。

- **会话列表**：按状态分组，分组头只有一行「标题 计数」；每行只显示状态图标与会话名（带子代理的会话多一个折叠箭头），目录、时长、分支与 Ctrl+数字 在悬停提示里；等待过久的会话名转为待处理色
  - 状态筛选条在会话达到 9 个时才常驻，计数为 0 的筛选片不显示；会话少时可用命令面板「筛选：…」，筛选生效期间筛选条一直显示
- **详情页头**：面包屑、状态（持续时间在悬停提示里）与续接类主操作；点项目名复制工作目录，导出终端输出、复制路径、复制会话 id、结束会话收在「⋯」菜单里
- **属性面板**按关键程度由上往下排列，没有内容的分区不显示：
  1. 状态：当前状态、待审批的工具与命令、状态标记（等待已久、只读、退出码、首条提示词未发送、待发送批注、批次方案）
  2. 自动验证（仓库已配置时）→ 改动（有改动时）→ 上下文（有统计数据时）→ 子代理（有子代理时）→ 最近活动（最近 3 条，标题旁「全部」打开时间线）
  3. 工作区（仅工作区会话）→ 属性（目录、会话 id、来源、创建时间）→ 对话；属性与对话默认折叠，展开状态会记住
- 不选中会话时显示有会话的状态计数总览
- 颜色、字号、圆角、阴影都收在 `renderer.css` 的 `:root` 变量里，样式表其他地方与 `index.html` 里写颜色字面量会被 `npm run check` 拦下

## 外观与换肤

- 三套深色皮肤：石墨（默认，黑白灰）、夜蓝（冷色，强调色偏蓝）、暖灰（暖色）。设置页「外观」点缩略卡片，或命令面板「切换皮肤：…」，即时生效，不重启、不重建终端
- 换肤覆盖界面、状态色、diff 与语法着色、终端 16 色、终端搜索高亮，以及标题栏和系统最小化 / 最大化 / 关闭按钮的颜色
- 偏好存在数据目录的 `appearance.json`；启动时主进程按它设窗口底色，preload 在页面脚本运行前设好皮肤，首帧不闪默认色。文件损坏时改名为 `.bak-<时间>` 留档并回退石墨
- 皮肤清单在 `src/shared/skins.ts`，配色在 `src/renderer/skins.css`（每套一个 `:root[data-skin="…"]` 块，石墨即 `:root` 默认值）。新增皮肤要覆盖全部颜色变量，`tests/skins.test.ts` 会核对两边一致；文字与状态色对底色的对比度不低于石墨

## 独立工作区与改动审阅

- **独立工作区**：新建会话时勾选「独立工作区」，面板在 `<仓库>/.claude/worktrees/nexus-xxxx` 用 `git worktree` 建一个独立分支（默认 `nexus/xxxx`，可自定义分支名与基线），会话在其中运行；多个会话改同一仓库互不干扰，工作区目录已写入 `.git/info/exclude`，不污染主目录的 `git status`
  - 结束会话时可选择保留或删除工作区，有未提交文件或未合并提交会二次确认
  - 残留工作区在命令面板（Ctrl+K）输入「工作区」即可清理
  - 依赖目录（如 `node_modules`）不会自动复制，需要时在工作区里重新安装
  - 合并回主分支可用会话详情的「收尾」标签（见下文），也可手动 `git merge nexus/xxxx`
- **改动审阅**：会话详情的「改动」标签页（Ctrl+Shift+D 与终端互切）列出改动文件和单文件 diff，Claude 每轮结束后自动刷新
  - 工作区会话可切换「相对基线」（含已提交内容）与「仅未提交」两种口径
  - 普通会话按仓库根统计；同一仓库有多个普通会话时，改动可能来自其他会话，面板会提示
  - 统计只用只读 git 命令（`GIT_OPTIONAL_LOCKS=0`），不与 Claude 自己的 git 操作抢锁；非 git 目录只提示不支持
- **整理改动列表**：文件多时可以搜索、折叠分组和清除记录
  - **搜索**：列表顶部的搜索框按文件名或路径过滤，多个词用空格隔开、需同时命中，不区分大小写；改动页内按 `/` 聚焦，`Enter` 回到列表，`Esc` 清空。仓库视角同样可用
  - **折叠分组**：本会话视角下点分组标题收起或展开该目录的文件，折叠状态按目录记住，重启后保留；折叠的文件不参与 `J` `K` 切换
  - **清除记录**：本会话视角下可清除单个文件（行悬停的 `✕`，直接清除）、整个目录（分组标题悬停的 `✕`，需确认）、全部记录（工具栏垃圾桶或命令面板「清除改动记录」，需确认）。清除是彻底删除：记录与改前快照一并删掉，这些文件不能再「撤销到改前」，磁盘上的文件本身不受影响；之后 Claude 再改动它们，会从那时的内容重新开始记录。由其他面板实例运行的只读会话不提供清除

## diff 高亮与分栏

- **语法高亮**：按扩展名着色（ts / js / py / vue / md / json 等常见语言），删增配对的行再标出变化的词；未识别的扩展名不着色但保留词级差异。只绘制可视区附近的行，大 diff 先显示首屏再分批补齐；单个文件 diff 超过 400KB 自动关闭高亮并提示
- **统一 / 分栏**：diff 工具栏切换，改动页内按 `V`（焦点不在终端和输入框时），或命令面板「切换 diff 视图（统一 / 分栏）」；分栏两侧等高、长行换行，切换时按行号对齐滚动位置
  - diff 区不足 640px 时暂按统一视图显示并提示，放宽后自动恢复，不改偏好
- 命令面板「开关语法高亮」；两个偏好都存在本机，重启后保留
- 批注在高亮与分栏下照常使用，分栏时按点中的一侧选行

## 改动批注

在改动页的 diff 上按行写修改意见，攒够了一次发给该会话的 Claude。

- **写批注**：点击 diff 行号栏选一行，拖动或按住 Shift 点击选一段（跨分块时截到分块末尾并提示），也可对整个文件写批注；`Ctrl+Enter` 保存、`Esc` 取消，只在批注卡片内生效
- **标记**：文件行显示「◆N」，改动标签与属性面板状态分区显示待发送条数；抽屉列出全部批注及其状态（有效 / 行号已偏移 / 已失效 / 排队中 / 已发送）。Claude 改了被批注的行时按内容重新定位，行号偏移的发送时自动采用新行号，找不到则标为失效，仍可发送
- **发送**：命令面板「发送批注给 Claude」或批注区的按钮，先预览整段消息
  - 会话空闲时直接发送；正忙时可选「立即发送」（交给 Claude Code 自己排队）或「排队」（本轮结束后自动发出）；等待权限时只能排队
  - 消息以一次 bracketed paste 加一次单独回车写入终端，多行内容不会被拆成多次提交；Claude 未开启粘贴模式时会提示风险
  - 输入框里若有没提交的半截文字会一起发出，面板不会清空输入框
- 批注存放在 `~/.claude-session-panel/annotations/<面板会话 id>.json`，会话与历史记录都不在了的批注文件在启动时清理

## 撤销单个文件

改动页里撤销某一个文件的改动，撤销前先备份，可以恢复。

- **入口**：改动列表行悬停的「↶」、diff 头部的「撤销」、列表右键菜单「撤销此文件」
- **行为**：已跟踪文件用 `git restore` 把工作区与暂存区恢复到 HEAD（「仅未提交」口径）或基线提交（「相对基线」口径）；未跟踪文件直接删除；重命名的新旧路径一起恢复。冲突文件与子模块不能撤销
- **确认**：确认框写明将执行的命令；Claude 正在运行时额外警告它可能马上又改这个文件；文件超过 50MB 时不备份，需再次确认「撤销后无法恢复」；恢复时文件在撤销后又被修改过，或 Claude 正在运行，都会先确认
- **恢复**：成功后改动页顶部显示「已撤销 X · 时间 [恢复] [✕]」横幅，命令面板也有「恢复最近一次撤销」
- 备份存放在 `~/.claude-session-panel/undo/<面板会话 id>/`，每个会话保留最近 10 次，超过 7 天或总量超过 200MB 时从最旧的开始清理

## 工作区收尾

独立工作区会话的详情区多一个「收尾」标签（Ctrl+Shift+F 与终端互切），在面板里完成提交、合并、推送、创建 PR。所有数字都来自实时执行的 git，打开标签、会话状态变化、操作结束后自动重新检查，也可点「⟳」。

- **状态头**：分支、相对基线的领先 / 落后、未提交数、上游，以及主工作区所在分支和是否干净
- **提交**：填写提交信息后提交（`git add -A` 时排除面板复制进工作区的本地配置，提交信息经临时文件 `git commit -F` 传入），可勾选「跳过提交钩子」
  - 「请 Claude 生成」根据改动调用一次 `claude -p` 生成提交信息（diff 截到 60KB，超时 90 秒），只在点击时调用
  - 「让本会话自己提交」把「检查改动并提交」的提示词发给本会话的 Claude
- **合并**：在主工作区执行 `git merge --no-ff`（或「仅快进 --ff-only」）。只有主工作区干净、在基线分支上、没有进行中的合并且主工作区里没有正在运行的会话时才可用，按钮置灰时悬停可看原因；合并前预检是否会冲突
  - 预检有冲突时可「让本会话先在工作区里把基线合进来」，在工作区里解决冲突后再合并
  - 合并出现冲突时三选一：开一个解决冲突的会话（工作目录为主工作区，Claude 就绪后自动发送带冲突文件列表的提示词）、放弃合并（`git merge --abort`）、稍后手动处理；主工作区处于合并中时收尾页一直提供这两个入口
  - 新会话迟迟没有就绪（30 秒）时提示词不会丢，改动页顶部提示，可手动「发送」或「放弃」，命令面板也有「发送准备好的提示词」
- **推送**：`git push -u <远端> <分支>`，多个远端时可选择，不提供强推；远端 URL 中的凭据在界面与记录里一律去掉
- **创建 PR**：已安装并登录 gh 时直接 `gh pr create`（未推送会先推送）；没有 gh 或未登录时降级为「复制命令」（复制等价的 `gh pr create` 命令）和「打开比较页」（主机名含 github 的打开 compare 页，含 gitlab 的打开新建合并请求页，其他主机不提供）
- **确认与记录**：每个写操作的确认框列出工作目录与完整命令；Claude 正在运行时需要二次确认。「操作记录」列出最近 5 条（命令、退出码、耗时），「全部」可查看每条的输出，每会话保留最近 50 条
- 命令面板（Ctrl+K）输入「收尾」可直达提交 / 合并 / 推送 / 创建 PR 分区；只读认领的会话所有写操作禁用
- 不做：squash 与变基合并、强制推送、在面板内编辑冲突

## 会话续接

面板为每个会话预先分配 Claude 会话 id（`--session-id`），进程退出、面板重启或会话结束后都能接着同一段对话继续（`--resume`）。

- **页头按钮**：进程已退出的会话在详情页头显示「续接对话」与「全新开始」
  - 续接：面板会话 id、标签、工作目录、已完成的子代理不变；对话记录缺失时按钮不出现并说明原因
  - 全新开始：换新的 Claude 会话 id，不带之前的上下文；旧 id 仍记在会话记录里
  - CLI 报找不到对话或续接后立即退出时标记「续接失败」，不自动重试，改给「全新开始」与「再试一次续接」
  - 进程仍在运行时的「续接重启」只放在命令面板，需确认
- **分叉**：命令面板「分叉为新会话」带着这段对话另开一个会话（`--resume <id> --fork-session`），原会话不受影响；同一段对话正被别的会话占用时也给出这个出路
- **退出与启动**：命令面板「退出时：询问 / 保留会话 / 结束会话」「启动时恢复：自动续接 / 询问 / 不恢复」
  - 保留的会话下次启动出现在侧栏「待续接」分组，询问档在列表上方显示横幅（全部续接 / 全部归档 / 稍后）；异常退出同样按待续接恢复
  - 待续接的行没有进程，终端区显示卡片，可单独续接、全新开始或归档
  - 系统注销、关机等未经确认框的退出一律按保留处理
- **历史**：结束的会话记录保留（默认最多 300 条、90 天，可在会话历史面板调整），首页「最近结束」列出最近 5 条，命令面板「历史」分组列出最近 10 条，可直接续接；独立工作区已删除但分支还在的，入口为「重建并续接」
- **孤儿会话接管**：面板异常退出后 claude 仍在原终端运行的会话，重启时按 pid 认领为只读（行上标「只读」），只能查看状态
  - 原终端无法重新挂回面板（终端句柄随旧面板进程失效），页头「接管并续接」或命令面板同名命令会在确认后结束原进程，再在面板里续接同一段对话；原终端里未提交的输入会丢失
  - 结束前核对该 pid 的命令行带着本会话专属的 `--settings` 配置路径，核对不上（pid 被复用、读不到命令行）一律不结束任何进程；续接条件不满足（如对话记录缺失）时也先拒绝、不动原进程
  - 原进程自行退出后只读自动解除，按普通的已退出会话续接或结束
- **属性面板「对话」分区**：Claude 会话 id（可复制）、对话记录是否存在及大小、续接次数、历史 id 数
- 记录存放在 `~/.claude-session-panel/records/<面板会话 id>.json`（一会话一文件，原子写入），设置在 `resume-settings.json`

## 上下文

面板读取 claude 自己写的对话记录（`CLAUDE_CONFIG_DIR`，缺省 `~/.claude`，下的 `projects/**/*.jsonl`），显示每个会话主线程的上下文占用。只读不写，增量、分块、异步读取，几十 MB 的记录首次接入时界面仍可操作；根目录之外的路径一律忽略。不计算金额：经网关或订阅使用时按官方价格估算的金额与实际账单无关。

- **属性面板「上下文」节**：「已用 / 窗口（百分比）」、占用条（绿 / 黄 / 红）、模型与窗口来源、压缩次数
- **上下文设置**（命令面板「上下文设置」、上下文节的「设置…」或设置页）：黄 / 红档阈值，按模型前缀覆盖上下文窗口；保存后已有会话立即按新窗口重算
- **口径**：上下文取最近一条主对话记录，不累加，子代理不计入；窗口依次取：设置里的窗口覆盖 → 模型 id 带 `[1m]`（含 claude 设置里 env 模型映射）→ 实际观测超过 200k 判为 1M → 内置表 → 200k
- **提醒**：会话上下文越过黄档、红档时各发一次系统通知（也可推送到群机器人），压缩后再次越档会再提醒，重启面板不重复
- **无数据**：claude 未写对话记录时属性面板不显示上下文节，原因记在日志 `usage` 标签下，不弹窗；面板从 Claude Code 内启动（继承了 `CLAUDE_CODE_CHILD`）时 claude 不写记录，原因里会注明
- 账本存放在 `~/.claude-session-panel/usage/ledger.json`（损坏时备份为 `ledger.json.bad-<时间戳>` 后重建），设置在同目录的 `settings.json`；旧版本的预算与单价设置读取时忽略
- `CLAUDE_PANEL_USAGE=0` 关闭上下文统计：不读对话记录，界面不显示上下文

## 终端搜索与导出

- **搜索**：终端标签内 Ctrl+F 打开搜索框（Ctrl+F 交给终端时用 Ctrl+Alt+F）；Enter / ↓ / F3 下一个，Shift+Enter / ↑ / Shift+F3 上一个，Esc 关闭并把焦点还给终端
  - 大小写、正则、全词三个开关；显示「当前 / 总数」，无匹配时输入框标红，正则写错只提示不报错
  - 覆盖整个滚动历史；子代理的只读终端同样可搜
- **导出**：页头「⋯」菜单或命令面板的「导出终端输出」，默认文件名 `<标签>-<yyyyMMdd-HHmm>`
  - 三种格式：纯文本（按屏幕重放，推荐）、纯文本（直接去除控制符）、原始 ANSI（`.log`）；前两种不含任何控制字符
  - 超过缓冲上限时文件头注明「仅包含最近 N 字符的输出」；进程已退出但仍在列表的会话可导出，没有输出缓冲的会话提示「无可导出的输出」

## 首条提示词、模板与批量派发

- **首条提示词**：新建表单可填写多行首条提示词（Ctrl+Enter 创建），Claude 就绪后自动作为一条消息提交；出现目录信任提示时等用户确认后才提交，未能送达的在属性面板状态分区标记，可在页头或命令面板重新发送、插入到输入框或放弃
- **模板**：命令面板「新建模板」「管理模板」，Ctrl+Shift+T 或 Ctrl+K 输入模板名、正文关键词直接命中
  - 「插入」只放进 Claude 输入框不提交，「插入并发送」直接提交；多行模板作为一条消息提交
  - 内置变量 `{{分支}}` `{{目录}}` `{{项目}}` `{{日期}}` `{{改动文件}}` 自动填充，`{{文件}}` 弹出文件选择，自定义变量与 `{{名称:默认值}}` 弹出填写表单，`\{{` 原样输出
  - 等待审批、只读认领、进程已退出时禁止插入并说明原因
  - 存放在 `~/.claude-session-panel/templates.json`，损坏时备份为 `.bak-<时间戳>` 后以空列表启动
- **批量派发**：新建表单勾选独立工作区并把方案数设为 2～N，同一条首条提示词派发给 N 个独立工作区会话（标签 `<任务> #1`～`#N`），单个失败不影响其余，全部失败不留工作区与分支
- **批次对比**：创建后自动打开，并排显示各方案的状态、耗时、相对基线的改动统计与验证结果；「保留此方案」先列出其余方案的未提交文件数与未合并提交数，确认后结束其余会话并删除其工作区与分支
  - 批次记录存放在 `batches.json`，重启后仍可从命令面板「打开批次对比」进入，会话全部结束的批次标为「已结束」

## 每轮自动验证

- 命令面板「配置验证命令」按仓库设置命令、开关与超时（默认 300 秒），工作区会话共用主仓库的配置；配置存在 `~/.claude-session-panel/verify.json`，不写入用户仓库
- 会话一轮结束后自动在会话目录运行，属性面板「自动验证」节显示运行中 / 通过 / 失败 / 超时；新一轮开始时正在跑的验证立即连同进程树结束并标为「已取消」
- 默认两轮之间工作区没有变化就跳过，沿用上次结果；全局最多同时运行 2 个，其余排队；验证进程以低优先级运行
- 失败输出可在属性面板「验证」分组查看（保留颜色、GBK 不乱码，超长保留头尾），完整日志可用外部程序打开；「把验证失败发给 Claude 修复」在会话空闲时把命令、退出码与输出末尾发给 Claude
- 结束会话、重启会话、退出面板时正在运行的验证进程树全部结束

## 会话历史

- 入口：导航轨「会话历史」按钮、Ctrl+Shift+H、命令面板「打开会话历史」、首页「最近结束」的「全部历史」
- 列表显示标签、目录、开始与结束时间、时长、首条提示词摘要与结束状态（主动结束 / 异常退出 / 随面板结束 / 旧版迁移），固定的排在最前
- 搜索覆盖标签、首条与最近一条提示词、目录、分支，多个词按 AND 组合、不区分大小写；可按目录、时间范围（今天 / 7 天 / 30 天 / 全部）、结束状态过滤
- 详情动作：续接（不可续接时说明原因）、在此目录新建、复制首条提示词、存为模板、固定、删除；删除只删记录，不删工作区，关联工作区仍在时给出跳到「清理工作区」的入口
- 底栏可修改保留策略（改后立即按新上限清理，固定的不受限制），「清空历史」需确认，有固定记录时可选择保留
- 命令面板输入关键词时最近 50 条历史参与匹配，回车打开该条详情
- 记录目录不可用时面板显示降级横幅，会话的创建与运行不受影响；记录文件损坏的改名为 `.bad` 留档并在面板提示跳过数

## 活动时间线

把所有会话发生的事按时间排成一条线，离开一阵回来时一眼看清「谁在什么时候做了什么」。

- **入口**：导航轨「活动时间线」按钮、Ctrl+Shift+L、命令面板「打开活动时间线」「查看本会话时间线」
- **内容**：会话开始与结束、状态变化（等待批准 / 输入、出错、失联）、回合结束、子代理、每轮验证、提交与合并、上下文告警；按天分组倒序，连续的工具调用合并为一行并原地更新
- **过滤**：按会话、类别、「仅需关注」；列表不在顶部时新事件先排队，滚到底自动加载更早的记录
- 点击一行跳到对应会话或子代理；属性面板「最近活动」显示本会话最近 3 条
- 日志存放在 `~/.claude-session-panel/activity/events.jsonl`，最多保留 5000 条、14 天

## 远程通知

人离开电脑时，把需要关注的事件推送到企业微信、钉钉或飞书的群机器人。

- **设置**：命令面板「远程通知设置」。最多 5 个目标，粘贴 webhook 地址自动识别平台；钉钉、飞书可填加签 secret，钉钉也可在机器人安全设置里用关键词 `Nexus`
- **事件**：等待批准、等待输入、本轮结束、出错 / 失联、上下文告警、等待超时，默认勾选等待批准、本轮结束、出错与上下文告警。用户自己结束会话不算出错
- **时机**：默认「仅离开时」——面板不在前台且系统空闲达到设定分钟数（默认 5）或已锁屏；也可选「始终」。可设静默时段（支持跨零点，如 22:00–08:00）
- **防打扰**：同一会话默认 60 秒内只推一条（出错与失联不受限），10 分钟内相同内容去重；每个目标每分钟最多 15 条，超出的条数附注在下一条里；连续失败 5 次暂停该目标 10 分钟，设置页显示恢复时间。失败不自动重试
- **内容**：会话名、状态、目录末级名称，可选附带命令摘要（已自动打码），不含完整路径
- **测试**：「发送测试消息」或目标行的「测试」用表单当前内容发送，绕过静默、节流、离开判定，目标行显示最近一次结果与耗时
- **安全**：只允许 https（本机回环地址除外）；地址里的令牌与 secret 用系统加密保存在 `~/.claude-session-panel/webhook.json`，界面与日志只显示脱敏地址，secret 不回显（留空即不修改）；系统加密不可用时设置页会提示
- 每一次跳过都在日志 `[webhook]` 下记一行原因（如 `skip quiet`、`skip throttle`、`skip circuit-open`），排查「为什么没收到」时先看这里

## 设置页

- **入口**：导航轨齿轮按钮、Ctrl+,、命令面板「打开设置」；返回、Esc、再按一次 Ctrl+, 或选中会话即关闭
- 左侧分节导航随滚动高亮，点击跳到对应分节；修改即时生效，无需保存
- **分节**：会话续接（退出时 / 启动时恢复）、会话历史（保留条数与天数，调小需确认并立即清理）、改动与 diff（统一 / 分栏、语法高亮）、每轮自动验证（并发数、失败通知，「配置当前仓库…」）、上下文（告警阈值与窗口覆盖）与远程通知（当前状态摘要，详细设置仍在各自的设置框）、快捷键（全部热键一览）、版本与更新
- 设置页打开时不带修饰键的单键热键（J/K、Y/N/A）不分发，避免误操作被挡住的会话

## 检查更新

- 从 GitHub Releases 安装的版本：到 [Releases 页](https://github.com/YesXXX/claude-nexus/releases) 下载新版安装包直接覆盖安装，会话记录与设置都在 `~/.claude-session-panel`，不受影响
- 团队内部分发：左下角「检查更新」可设置一个更新目录（可填局域网共享文件夹），之后启动和从托盘唤起时自动检查；客户端用内嵌公钥验签清单、校验安装包大小与 sha256 后才拉起安装器，被篡改的包一律拒绝。发布方的做法见 [发布流程](发布流程.md)

## 安全

- 主窗口只显示面板自己的页面：页面里点到的外部链接（如验证输出里的超链接）改用系统浏览器打开，其他导航与新窗口一律拦截；页面带内容安全策略，不执行内联脚本
- 全部 IPC 只接受面板页面主框架的调用，即使窗口被意外导航到外部网页，那个网页也调不动面板接口
- hook 上报服务只监听 `127.0.0.1`，每次启动随机生成令牌写在 `~/.claude-session-panel/receiver.token`，缺令牌、令牌不对、不是 JSON 或请求体超过 1MB 的上报一律拒绝，日志记 `拒绝请求`

## 排障

日志在 `~/.claude-session-panel/logs/`，提 issue 时附上最新一份日志的相关片段（注意先去掉路径里的敏感信息）。

- 会话状态一直不更新：查最新日志的「hook-client 路径」行，安装版应指向 `app.asar.unpacked\scripts\hook-client.js` 且文件存在；同时确认 `node` 在 PATH 里（hook 由 Claude Code 用 `node` 执行）
- 新建会话后终端立即退出：在普通终端里运行 `claude --version`，确认 Claude Code 已安装且 `claude` 在 PATH 里
- 系统通知不显示：确认 Windows 通知设置允许 Claude Nexus；开发态运行时通知依赖面板自动写入的开始菜单快捷方式
- 检查更新提示签名无效：清单不是用内嵌公钥对应的私钥签的，或发布后被改动过，日志 tag 为 `update`
- 自己编译的安装版启动闪退或白屏：多为 node-pty 原生模块与 Electron 版本不匹配，见 [开发指南](开发指南.md) 的「出包」一节
