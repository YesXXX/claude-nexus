# 开发指南

## 环境

- Windows 10 / 11 x64（目前只支持 Windows）
- Node.js 22.4 及以上（vitest 4 与 e2e 需要；推荐 24）
- Git，以及已安装并能在终端运行的 [Claude Code](https://docs.anthropic.com/claude-code)（开发时也可以全程用 mock，见下文 e2e）

```bash
git clone https://github.com/YesXXX/claude-nexus.git
cd claude-nexus
npm install
npm start
```

## 常用命令

- `npm start` 开发态运行（默认开 DevTools；`CLAUDE_PANEL_DEVTOOLS=0` 关闭）
- `npm test` 单元测试（vitest）
- `npm run e2e` 端到端测试（见下文）
- `npm run verify`：类型检查 + 渲染层静态检查 + 单元测试，提交前跑一遍

想在不消耗真实额度的情况下体验界面：设置 `CLAUDE_PANEL_HOME=<任意空目录>` 和 `CLAUDE_PANEL_MOCK_CLAUDE=1` 后 `npm start`，面板会用独立数据目录，并用 `scripts/mock-claude.js` 代替真实的 claude。

## 出包

- `npm run dist:unsigned`：出未签名的安装包，产物在 `release/`，适合自己编译自己用
- `npm run dist`：出包并签名更新清单，需要发布私钥，见 [发布流程](发布流程.md)
- 国内网络下载 Electron 不稳时加镜像：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run dist:unsigned`
- node-pty 自带 N-API 预编译模块（`node_modules/node-pty/prebuilds/win32-x64/`），一般不需要重编译；安装版启动闪退或白屏且该目录缺失时，装好 VS Build Tools 后执行 `npm run rebuild` 再出包

## 提交前检查

- `npm run check`：渲染层静态检查。渲染层没有打包器，浏览器按相对路径逐个加载 ESM，这些问题只会在运行时以白屏暴露，所以单独拦截：
  - 相对路径的运行时导入必须带 `.js` 后缀；只用于类型的导入写 `import type`
  - 运行时导入不得成环
  - 分层：`core` → `ui` → `term` → `actions` → `features` → `views` / `input` → `builtin` → 入口 `renderer.ts`，低层不导入高层（类型导入同样受限）；`features` 只依赖 `core` 与 `ui`
  - 每个文件不超过 500 行，入口 `renderer.ts` 不超过 300 行；渲染层根目录只放入口
  - `tests/e2e` 不得导入 `src/renderer` 下的模块
- `npm run typecheck`：主进程、渲染层与 `tests/**`、`scripts/e2e/**` 的类型检查
- `npm run verify`：`typecheck` + `check` + `test`，提交前跑一遍

## 渲染层扩展点

新功能放在 `src/renderer/features/<功能>/`，导出 `install(ctx: AppContext)`，在入口 `renderer.ts` 装配内置项之后调用。通过 `ctx.registry` 注册，不改视图模块：

- `registerCommands`：命令面板条目（provider 同步返回条目，可选 `refresh` 在打开面板时刷新缓存）
- `registerHotkey`：全局热键（`always` / `outside-input` 两段，同段按键不得重复，自动出现在设置页快捷键分节）
- `registerSettingsSection`：设置页分节（`render` 返回分节内容，每次打开设置页重新调用；返回 null 不显示），控件用 `ui/settings-kit` 的设置行、分段、开关、数字框
- `registerStatusBadge`：属性面板「状态」分区里的标记（纯同步，只读 `Session` 字段）
- `registerDetailTab`：详情标签（按钮 `#tab-<名称>`，宿主 `#<名称>-host`，首次切到时 `create`）
- `registerInspectorSection` / `registerPaneAction` / `registerPaneMenuItem`：属性面板分区（返回 null 不显示，没内容时不要占位）、详情页头按钮（只放续接这类主操作）、页头「⋯」菜单项
- `registerTermCover`：终端区覆盖层（如待续接会话的卡片），返回 null 表示不覆盖
- `registerOpener` / `findOpener`：按 id 登记可被其他功能调用的打开入口（如「全部历史」）

id 形如「功能.名称」，内置项用 `core.` 前缀占 order 0~499，功能模块从 500 起。属性面板分区例外：按关键程度以百为档排列（状态 0、自动验证 100、改动 200、上下文 300、子代理 400、最近活动 500、工作区 600、属性 700、对话 800），新分区插在对应档位之间。

## e2e 测试

`npm run e2e` 构建后启动隔离的面板实例（系统临时目录下 `nexus-e2e-*` 的独立 home，不碰 `~/.claude-session-panel` 与 `~/.claude`），通过 CDP 逐个运行 `tests/e2e/*.e2e.ts`，结束后清理自己启动的进程与临时目录（上次被强制中断留下的 `nexus-e2e-*` 目录也会在下次运行时清掉）。

- `npm run e2e -- --no-build`：跳过构建
- `npm run e2e -- 09-palette`：只跑文件名包含过滤词的用例
- `npm run e2e -- --port 9345`（或 `E2E_PORT`）：默认端口 9335 被占用时换端口；占用方不会被结束
- `npm run e2e -- --packaged`：针对 `electron-builder --win --dir` 产出的 `release/win-unpacked` 运行（默认端口 9336）
- `npm run e2e -- --keep`：保留临时根目录供排查
- 失败时页面截图（仅 CDP 页面截图）、控制台、DOM 快照与实例日志保存在 `.e2e-out/<时间戳>/<用例>/`

约定：一个场景一个文件，文件名带两位序号（如 `07-changes.e2e.ts`）；断言只基于 DOM 与 `window.panelApi`；`npm test` 不收录 e2e 用例。

隔离实例里的 claude 是 `scripts/mock-claude.js`：支持 `--session-id` / `--resume` / `--fork-session`，每轮任务往 `<home>/mock-claude/projects/<目录>/<id>.jsonl` 写一行对话记录（`CLAUDE_PANEL_TRANSCRIPT_ROOT` 可改根目录），输入 `/exit` 以退出码 0 退出；`CLAUDE_PANEL_MOCK_RESUME_FAIL=1` 让续接一律报找不到对话。

上下文相关的 mock 行为：
- 只有显式设置 `CLAUDE_PANEL_TRANSCRIPT_ROOT` 时，每轮才写带用量的 assistant 记录：opus-5 上下文 121000（1M 窗口的 12%）
- 任务文本含 `big` 时上下文约 850k（85%，触发上下文提醒）；含 `unknown` 时模型为 `mock-unknown-1`（不在内置窗口表里，按 200k）；含 `sub` 时额外写一个子代理记录；含 `compact` 时先写一条压缩边界
- `CLAUDE_PANEL_MOCK_NO_TRANSCRIPT=1` 不写对话记录（无数据场景），`CLAUDE_PANEL_MOCK_MODEL` 改用量记录里的模型
- `useApp({ env })` 的取值可用占位符 `{root}`、`{home}`、`{work}`、`{claude}`，启动时替换为本次临时根目录、面板 home、工作目录根与假 claude 配置目录，如 `CLAUDE_PANEL_TRANSCRIPT_ROOT: '{claude}/projects'`

需要模拟「退出后再打开」时用 harness 的 `app.restart()`，它保留同一临时根目录重启实例。

批注与收尾相关的自测开关（只在隔离实例生效，正式实例设置了也忽略）：
- mock 启动时上报 `SessionStart` 并输出 `ESC[?2004h`（粘贴模式开启），每读到一行上报 `UserPromptSubmit`；一次粘贴被识别为一条任务；`CLAUDE_PANEL_MOCK_INPUT_LOG` 记录原始 stdin；`-p` 模式输出固定的提交信息
- `CLAUDE_PANEL_PTY_TRACE=<文件>`：面板每次写 pty 追加一行 `{"t","id","data"}`，用于核对发出的字节（如 `ESC[200~…ESC[201~` 加单独的 `\r`）
- `CLAUDE_PANEL_OPEN_EXTERNAL_LOG=<文件>`：打开外部链接时只记录 `{"t","url"}`，不真的打开浏览器

时间线与远程通知相关的自测开关：
- `CLAUDE_PANEL_TEST_HOOKS=1`：开放 `panelApi.activity.testReport`，直接上报活动事件（如上下文告警），只在隔离实例生效
- `CLAUDE_PANEL_WEBHOOK_LOOPBACK_ONLY=1`：webhook 只允许发往本机回环地址，外部地址一律拒绝且不发请求
- `CLAUDE_PANEL_WEBHOOK_AWAY=1` / `0`：把离开判定固定为离开 / 在场，只在隔离实例生效
- `tests/fixtures/fake-webhook-server.js` 在 `127.0.0.1` 随机端口模拟群机器人，记录收到的请求，可设定返回的 errcode、状态码或不回应
